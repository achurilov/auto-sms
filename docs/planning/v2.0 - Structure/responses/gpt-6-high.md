**Анализ требований**

Для первого запуска предлагается **Android-приложение, серверное API и веб-панель администратора**. Отправка выполняется через SIM-карту устройства после подтверждения пользователем.

iOS не подходит для исходного сценария: стандартный интерфейс Apple предполагает участие пользователя в отправке сообщения и не предоставляет обычному приложению автоматическую массовую отправку через SIM. [Документация Apple](https://developer.apple.com/documentation/messageui/mfmessagecomposeviewcontroller)

До начала основной разработки необходимо согласовать:

| Вопрос          | Предлагаемая граница MVP                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------- |
| Устройства      | Android 10 и выше; конкретные модели подтверждаются испытаниями                                             |
| Объём           | До 100 уникальных получателей за рассылку; суточный лимит определяется после проверки оператора и устройств |
| Распространение | Подписанный APK для контролируемого круга пользователей                                                     |
| Запуск          | Вручную из приложения, без расписания                                                                       |
| SIM-карты       | Выбор одной активной SIM перед запуском                                                                     |
| Интернет        | Обязателен для подготовки рассылки; после загрузки получателей отправка может продолжаться без интернета    |
| Параллельность  | Одна активная рассылка на устройстве                                                                        |

Это исходные проектные допущения, а не ограничения, заданные заказчиком.

**Функции пользователя:**

* Авторизация и просмотр доступных групп с количеством контактов.
* Выбор одной или нескольких групп.
* Ввод текста, отображение количества уникальных получателей и SMS-сегментов.
* Подтверждение отправки с указанием выбранной SIM.
* Просмотр прогресса, приостановка, продолжение и отмена оставшейся очереди.
* История рассылок с результатами по получателям.

**Функции администратора:**

* Создание, редактирование и архивирование групп.
* Добавление контактов вручную и импорт CSV с отчётом об ошибках.
* Назначение пользователям доступа к группам.
* Управление пользователями, лимитами и списком исключённых номеров.
* Просмотр журнала рассылок и административных изменений.

**Правила обработки данных:**

* Номера нормализуются в международный формат; некорректные номера не допускаются к отправке.
* Один номер, входящий в несколько выбранных групп, получает одно сообщение в рамках рассылки.
* Состав получателей и текст фиксируются при подтверждении. Последующее редактирование группы не меняет запущенную рассылку.
* Пользователь не может менять группы и контакты ни через интерфейс, ни прямым запросом к API.
* Получатели получают отдельные SMS и не видят номера других адресатов.
* Для MVP не предусматриваются вложения, MMS, обработка входящих SMS и персонализация текста.

**Архитектура системы**

| Компонент                       | Ответственность                                                           |
| ------------------------------- | ------------------------------------------------------------------------- |
| Android-приложение              | Интерфейс, локальная очередь, отправка через SIM, обработка результатов   |
| Серверное API                   | Авторизация, права доступа, группы, подготовка рассылок, сбор результатов |
| База данных                     | Пользователи, контакты, группы, рассылки, получатели, события             |
| Веб-панель                      | Управление данными и просмотр истории                                     |
| Эксплуатационная инфраструктура | HTTPS, резервные копии, мониторинг, доставка обновлений                   |

Сервер реализуется как один модульный сервис. Серверный брокер сообщений для MVP не требуется: очередь фактической отправки находится на телефоне.

**Порядок выполнения рассылки:**

1. Приложение получает доступные группы через API.
2. Передаёт выбранные группы и текст для подготовки рассылки.
3. Сервер проверяет права, исключает запрещённые номера, устраняет дубли и создаёт неизменяемый список получателей.
4. Приложение загружает список, рассчитывает сегменты и показывает итоговое подтверждение.
5. После подтверждения сервер закрепляет рассылку за устройством. Приложение сохраняет очередь локально и запускает отправку.
6. Результаты сохраняются локально и передаются на сервер. При отсутствии интернета синхронизация откладывается.

Для API предусматриваются операции:

| Операция                                           | Назначение                                 |
| -------------------------------------------------- | ------------------------------------------ |
| `GET /groups`                                      | Доступные пользователю группы              |
| `POST /campaigns/prepare`                          | Подготовка списка получателей              |
| `POST /campaigns/{id}/start`                       | Подтверждение и закрепление за устройством |
| `GET /campaigns/{id}/recipients`                   | Загрузка получателей                       |
| `POST /campaigns/{id}/events`                      | Пакетная передача результатов              |
| `/admin/groups`, `/admin/contacts`, `/admin/users` | Административные операции                  |

Создание и запуск защищаются ключами идемпотентности, события — уникальными идентификаторами. Повтор HTTP-запроса не должен создавать новую рассылку.

**Надёжность отправки:**

* Перед обращением к SMS API попытка записывается в локальную БД.
* Состояния: «В очереди», «Отправляется», «Отправлено», «Ошибка», «Результат неизвестен», «Отменено». Подтверждение доставки учитывается отдельно.
* Для составного сообщения фиксируется результат каждого сегмента.
* После аварийного завершения сообщения с неизвестным результатом автоматически не повторяются.
* После перезагрузки устройства продолжение требует действия пользователя.
* Отмена останавливает новые отправки; уже переданное телефонному модулю сообщение отозвать нельзя.

**Гарантировать отправку ровно один раз невозможно:** между передачей SMS системе и сохранением результата приложение может завершиться. Поэтому неопределённый результат должен быть явно виден пользователю, а повтор — выполняться осознанно.

**Технологический стек**

| Слой                    | Технологии и применение                                                                            |
| ----------------------- | -------------------------------------------------------------------------------------------------- |
| Android                 | Kotlin, Jetpack Compose, ViewModel, Coroutines                                                     |
| Локальные данные        | Room: очередь, попытки отправки, неподтверждённые сервером события                                 |
| SMS                     | `SmsManager`, экземпляр для выбранной SIM, `divideMessage`, отправка обычных и составных сообщений |
| Выполнение рассылки     | Foreground Service с уведомлением о прогрессе, запускаемый из открытого приложения                 |
| Фоновая синхронизация   | WorkManager для передачи сохранённых результатов на сервер                                         |
| API-клиент              | Retrofit/OkHttp                                                                                    |
| Сервер                  | Python, Django, Django REST Framework                                                              |
| Административная панель | Django Admin с формой импорта CSV и ограничениями доступа                                          |
| База данных             | PostgreSQL                                                                                         |
| Развёртывание           | Docker Compose, Nginx, HTTPS                                                                       |
| Контракт API            | OpenAPI                                                                                            |

Django Admin позволяет выпустить административную часть без отдельной разработки веб-интерфейса.

На Android потребуется разрешение `SEND_SMS`; разрешения для выбора SIM запрашиваются по требованиям используемых API. Чтение телефонной книги и входящих SMS для основного сценария не требуется. `SmsManager` поддерживает результаты отправки и отчёты о доставке через отдельные callbacks. [Документация Android](https://developer.android.com/reference/android/telephony/SmsManager)

Тип Foreground Service необходимо обосновать для целевых версий Android. Для данного сценария следует проверить применимость `specialUse`; наличие сервиса не гарантирует непрерывную работу при принудительной остановке приложения. [Требования к foreground services](https://developer.android.com/develop/background-work/services/fgs/service-types)

Защита данных: HTTPS, проверка прав на сервере, хранение секретов с использованием Android Keystore, исключение номеров и текстов из технических логов. Для локальных данных устанавливаются срок хранения и очистка; доступ к истории на сервере ограничивается ролями.

**План разработки**

| Этап                      | Конкретные работы                                                                                                       | Результат этапа                                            |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 1. Уточнение требований   | Определить объёмы, устройства, операторов, права, правила повторов, сроки хранения данных                               | Согласованные сценарии и критерии приёмки                  |
| 2. Проверка реализуемости | Создать прототип отправки; проверить выбранную SIM, длинные SMS, выключенный экран, ограничения частоты и установку APK | Протокол испытаний и решение о продолжении                 |
| 3. Проектирование         | Подготовить экраны, модель данных, состояния очереди и OpenAPI                                                          | Контракт для параллельной разработки                       |
| 4. Сервер и админ-панель  | Реализовать авторизацию, группы, импорт CSV, доступы, подготовку рассылки и приём событий                               | Работающая административная часть и API                    |
| 5. Мобильный интерфейс    | Реализовать вход, выбор групп, редактор, подтверждение, прогресс и историю                                              | Полный пользовательский сценарий                           |
| 6. Механизм отправки      | Реализовать очередь, SIM, сегментацию, callbacks, паузу, отмену, восстановление и синхронизацию                         | Рабочая отправка с обработкой сбоев                        |
| 7. Интеграция и испытания | Проверить реальные устройства, безопасность, аварийные сценарии и нагрузку                                              | Релиз-кандидат                                             |
| 8. Пилот и выпуск         | Установить приложение небольшой группе пользователей, собрать результаты, исправить дефекты                             | Подписанный APK, сервер, инструкции и процедура обновления |

**Основную разработку следует начинать после этапа 2.** Если нужный объём нельзя отправить в допустимое время через выбранные SIM и устройства, необходимо пересмотреть объём или способ доставки до затрат на полный продукт.

**Тестирование и критерии приёмки**

Используются автоматические тесты серверных правил и очереди, интеграционные тесты API и испытания SMS на реальных устройствах. Эмуляторы не заменяют проверку операторской связи.

| Проверка              | Критерий приёмки                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Пересечение групп     | Группы на 40 и 30 номеров с 10 общими номерами создают ровно 60 получателей                                                          |
| Права пользователя    | Попытки изменить контакты или использовать чужую группу отклоняются сервером                                                         |
| Импорт CSV            | Для каждой ошибочной строки указаны номер строки и причина; некорректные номера не попадают в рассылку                               |
| Выбор SIM             | На двухсимочном устройстве SMS отправляются через подтверждённую SIM; при её отключении очередь приостанавливается                   |
| Текст                 | Проверены кириллица, латиница, emoji и границы сегментов; предпросмотр соответствует фактическому разбиению                          |
| Повтор нажатия        | Двойное нажатие и повтор сетевого запроса создают одну рассылку                                                                      |
| Потеря интернета      | Загруженная очередь сохраняется; накопленные результаты синхронизируются после восстановления связи без дублей событий               |
| Потеря мобильной сети | Ошибка или ожидание отражаются явно; отсутствует бесконечный цикл повторов                                                           |
| Завершение процесса   | Очередь восстанавливается; подтверждённо отправленные сообщения не отправляются повторно; неопределённые выделяются отдельно         |
| Частичная отправка    | Успех части сегментов не отображается как успешная отправка всего сообщения                                                          |
| Пауза и отмена        | После обработки команды новые сообщения не передаются на отправку; уже переданные учитываются отдельно                               |
| Статусы               | «Доставлено» появляется только при соответствующем подтверждении; отсутствие отчёта не считается ошибкой отправки                    |
| Пилотная нагрузка     | Очередь на 100 получателей проходит без потери записей и зависания интерфейса; реальные отправки выполняются в согласованных лимитах |
| Развёртывание         | Проверены установка, обновление без потери очереди и восстановление серверной БД из резервной копии                                  |

Матрица устройств должна включать минимум три реальные модели, нижнюю и верхнюю поддерживаемые версии Android, двухсимочное устройство и операторов будущего пилота.

Выпуск допускается после прохождения обязательных сценариев и устранения дефектов, вызывающих отправку неверному получателю, неконтролируемые повторы, потерю очереди или нарушение доступа.

**Риски и способы их снижения**

| Риск                                       | Способ снижения                                                                                                                                                                    |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ограничения Google Play                    | Для MVP использовать контролируемую установку APK. Публикацию в Play оценивать отдельно: доступ к SMS-разрешениям ограничен политикой и требует соответствия разрешённому сценарию |
| Лимиты Android и оператора                 | Проверить на прототипе, согласовать допустимое использование SIM, задать лимиты сегментов и интервалы. При ограничении приостанавливать очередь                                    |
| Блокировка SIM за массовую отправку        | До пилота подтвердить условия тарифа и допустимый объём у оператора; не обещать скорость без испытаний                                                                             |
| Остановка фоновой работы                   | Испытать целевые модели, сохранять очередь после каждого изменения, обеспечить ручное продолжение                                                                                  |
| Повтор SMS после сбоя                      | Хранить попытки до отправки, отдельно учитывать неопределённые результаты, исключить их автоматический повтор                                                                      |
| Недостоверные ожидания доставки            | Разделять отправку, доставку и отсутствие отчёта; не обещать доставку всем адресатам                                                                                               |
| Неожиданные расходы                        | Показывать количество сегментов перед запуском; денежную оценку выводить только при настроенном тарифе                                                                             |
| Утечка контактов                           | Минимизировать локальные данные, ограничить доступ, очищать кеш, маскировать логи                                                                                                  |
| Нежелательные рассылки                     | Учитывать согласия и исключённые номера, вести аудит, проверять требования страны эксплуатации до запуска                                                                          |
| Устаревшие данные при работе без интернета | Зафиксировать правило: изменения администратора действуют для следующих рассылок; немедленный отзыв уже загруженной очереди без связи невозможен                                   |

Google Play не предоставляет автоматического допуска к `SEND_SMS` только потому, что приложение используется внутри компании. Допустимость конкретного сценария необходимо проверять по политике магазина. [Политика SMS-разрешений Google Play](https://support.google.com/googleplay/android-developer/answer/10208820?hl=en)

**Оценка сроков**

Оценка дана для команды: **один Android-разработчик, один backend-разработчик, QA на половину ставки**, аналитик и DevOps — по необходимости. Сервер и мобильная часть разрабатываются параллельно.

| Работы                                | Длительность | Период       |
| ------------------------------------- | -----------: | ------------ |
| Требования и технический прототип     |   1–2 недели | Недели 1–2   |
| Архитектура, интерфейсы, контракт API |     1 неделя | Неделя 3     |
| Сервер и административная панель      |   2–3 недели | Недели 4–6   |
| Android-приложение и очередь отправки |   3–4 недели | Недели 4–7   |
| Интеграционные и приёмочные испытания |   1–2 недели | Недели 8–9   |
| Пилот и исправления                   |   1–2 недели | Недели 10–11 |

**Плановый срок запуска — 9–11 недель; с резервом на особенности устройств — до 13 недель.** Одному разработчику на весь объём потребуется ориентировочно 16–22 недели.

Оценка предполагает готовность заказчика предоставить устройства, SIM-карты и тестовых получателей в первую неделю. Публикация в Google Play, отдельный интерфейс администрирования и изменение способа доставки в эту оценку не входят.

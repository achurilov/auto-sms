# План разработки мобильного приложения для автоматизированной рассылки SMS

## 1. Анализ требований и архитектура системы

### 1.1. Функциональные требования
**Мобильное приложение (пользователь):**
- Авторизация пользователя
- Просмотр списка доступных групп контактов
- Выбор одной/нескольких групп
- Ввод текста SMS-сообщения
- Отправка сообщений через SIM-карту устройства
- Просмотр истории/статуса рассылок
- Отображение прогресса отправки

**Административная часть (веб-панель):**
- Управление пользователями мобильного приложения
- Создание/редактирование/удаление групп контактов
- Добавление/импорт контактов в группы (вручную, CSV/Excel)
- Просмотр статистики рассылок

### 1.2. Архитектура решения

```
┌─────────────────┐         ┌──────────────────┐
│  Мобильное       │ ◄─────► │   Backend API    │
│  приложение      │  REST   │   (сервер)       │
│  (Android/iOS)   │  HTTPS  │                  │
└────────┬─────────┘         └────────┬─────────┘
         │                            │
         │ SMS API                    │
         ▼                            ▼
┌─────────────────┐         ┌──────────────────┐
│  SIM-карта       │         │   База данных    │
│  устройства      │         │   (PostgreSQL/   │
└─────────────────┘         │    MySQL)        │
                             └────────┬─────────┘
                                      │
                             ┌────────▼─────────┐
                             │  Веб-панель       │
                             │  администратора   │
                             └───────────────────┘
```

### 1.3. Технологический стек (рекомендуемый)

**Backend:**
- Язык: Node.js/Python (Django/FastAPI) или Java (Spring Boot)
- База данных: PostgreSQL
- Аутентификация: JWT токены
- API: REST/GraphQL

**Mobile:**
- Кроссплатформенный: Flutter или React Native
- Нативный Android: Kotlin (если только Android, т.к. iOS не даёт прямого доступа к SMS API)
- **Важно:** нативный доступ к SMS API есть только у Android (iOS ограничивает отправку SMS программным путём)

**Admin Panel:**
- React/Vue.js + Admin Dashboard framework (React Admin, Vue Admin)

## 2. Детальный план разработки (по этапам)

### Этап 0: Подготовка (1-2 недели)
- Формирование детального ТЗ
- Прототипирование UI/UX (Figma)
- Проектирование БД (ER-диаграмма)
- Проектирование API (OpenAPI/Swagger спецификация)
- Настройка инфраструктуры (серверы, CI/CD, репозитории)

**Структура БД (основные сущности):**
```sql
- users (id, phone, name, role, status, created_at)
- groups (id, name, description, created_by, created_at)
- contacts (id, phone, name, additional_info)
- group_contacts (group_id, contact_id) -- связь many-to-many
- sms_campaigns (id, user_id, message_text, created_at, status)
- sms_campaign_groups (campaign_id, group_id)
- sms_logs (id, campaign_id, contact_id, phone, status, sent_at, error_message)
```

---

### Этап 1: Backend разработка (3-4 недели)

**Спринт 1.1: Базовая инфраструктура**
- Настройка проекта, окружений (dev/stage/prod)
- Настройка БД, миграции
- Система аутентификации/авторизации (JWT)
- Роли: Admin, User

**Спринт 1.2: API для администратора**
- CRUD для пользователей
- CRUD для групп контактов
- CRUD для контактов
- Импорт контактов (CSV/Excel парсинг)
- Привязка контактов к группам

**Спринт 1.3: API для мобильного приложения**
- Endpoint авторизации пользователя
- GET /groups — получение списка доступных групп
- GET /groups/{id}/contacts — получение контактов группы
- POST /campaigns — создание записи о рассылке (для логирования)
- POST /campaigns/{id}/logs — отправка статусов доставки на сервер
- GET /campaigns/history — история рассылок пользователя

**Спринт 1.4: Тестирование backend**
- Unit-тесты
- Интеграционные тесты API
- Нагрузочное тестирование (если предполагается много контактов)

---

### Этап 2: Мобильное приложение (4-5 недель)

**Спринт 2.1: Базовая настройка**
- Инициализация проекта
- Настройка навигации
- Настройка работы с API (HTTP клиент, интерцепторы)
- Экран авторизации

**Спринт 2.2: Основной функционал**
- Экран списка групп (с чекбоксами для мультивыбора)
- Экран ввода текста сообщения (со счётчиком символов, разбивкой на части при превышении 160 символов)
- Кнопка "Отправить"
- Предпросмотр: количество получателей, текст сообщения

**Спринт 2.3: Реализация SMS-отправки (Android)**
- Запрос разрешений: `SEND_SMS`, `READ_PHONE_STATE`
- Реализация через `SmsManager`:
```kotlin
val smsManager = SmsManager.getDefault()
smsManager.sendTextMessage(phoneNumber, null, message, sentPI, deliveredPI)
```
- Обработка длинных сообщений (`sendMultipartTextMessage`)
- Реализация очереди отправки (throttling — задержка между отправками, чтобы избежать блокировки оператором/системой, обычно 1-3 сек)
- Обработка BroadcastReceiver для статусов отправки/доставки

**Спринт 2.4: UI прогресса и результатов**
- Progress bar / счётчик "Отправлено X из Y"
- Экран результатов (успешно/ошибка по каждому номеру)
- Отправка логов на сервер по завершении/в процессе

**Спринт 2.5: История и дополнительные экраны**
- Экран истории рассылок
- Профиль пользователя
- Настройки (интервал отправки, повтор при ошибке)

**Важные технические нюансы для реализации:**
- Ограничения Android на массовую отправку SMS (начиная с определённых версий Android есть лимиты — не более 30 SMS в течение 30 минут без спец. разрешений на некоторых прошивках/операторах)
- Обработка двух SIM-карт (dual SIM) — выбор SIM для отправки
- Обработка отсутствия сети/баланса
- Фоновая отправка (Foreground Service), чтобы процесс не прерывался при сворачивании приложения

### Этап 3: Веб-панель администратора (3 недели)

**Спринт 3.1:**
- Авторизация администратора
- Дашборд со статистикой

**Спринт 3.2:**
- Управление пользователями (создание, блокировка)
- Управление группами и контактами
- Импорт/экспорт контактов

**Спринт 3.3:**
- Просмотр логов и статистики по рассылкам
- Отчёты (успешность доставки, активность пользователей)

---

### Этап 4: Интеграционное тестирование (2 недели)

- End-to-end тестирование полного цикла: администратор создаёт группу → пользователь видит группу → отправляет SMS → лог появляется у администратора
- Тестирование на реальных устройствах с реальными SIM-картами разных операторов
- Тестирование edge-кейсов: нет сети, нет баланса, некорректные номера, dual SIM
- Тестирование производительности при больших группах контактов (1000+)
- Security-тестирование (защита API, шифрование данных)

---

### Этап 5: Подготовка к релизу (1-2 недели)

- Публикация backend на production-сервер
- Настройка мониторинга (Sentry, логирование)
- Публикация приложения в Google Play (учитывая политику Google по SMS-приложениям — **важно**: Google ужесточил требования к приложениям с доступом SEND_SMS, нужно обосновать использование в Play Console, приложение может быть отклонено, если не относится к разрешённым категориям, например default SMS handler)
- Подготовка пользовательской документации
- Обучение администраторов

---

### Этап 6: Поддержка и развитие (постоянно)

- Мониторинг ошибок
- Сбор обратной связи от пользователей
- Возможные доработки:
    - Шаблоны сообщений
    - Планирование отправки (по расписанию)
    - Персонализация сообщений (подстановка имени контакта)

    - Аналитика эффективности рассылок

## 3. Риски и особенности, требующие внимания

| Риск | Описание | Митигация |
|---|---|---|
| **Google Play политика** | Google строго ограничивает публикацию приложений с SEND_SMS для массовых рассылок | Заранее изучить Google's SMS/Call Log permissions policy, возможно потребуется быть default SMS app или распространение вне Play Store (APK, MDM) |
| **iOS ограничения** | iOS не позволяет программно отправлять SMS без взаимодействия пользователя | Рассмотреть только Android или использовать iOS Message Extension с ручным подтверждением каждого сообщения |
| **Лимиты операторов** | Массовая отправка может блокироваться оператором как спам | Добавить настраиваемые задержки, ограничение количества за период |
| **Стоимость SMS** | Каждое SMS тарифицируется оператором пользователя | Информировать пользователя о количестве и предполагаемой стоимости перед отправкой |
| **Безопасность данных** | Персональные данные контактов | Шифрование при передаче (HTTPS) и хранении, соответствие 152-ФЗ/GDPR |

Ниже представлен подробный план разработки мобильного приложения для автоматизированной СМС-рассылки в соответствии с вашими требованиями.

# План разработки мобильного приложения "СМС-Рассылка"

## 1. Этап анализа и планирования (Discovery Phase)
**Цель:** Сформировать четкое видение продукта, определить его границы и технические требования.

*   **1.1. Определение целевой аудитории:**
    *   Малый бизнес (кафе, салоны красоты, магазины).
    *   Организаторы мероприятий.
    *   Руководители небольших коллективов.
*   **1.2. Формирование User Stories (Пользовательские истории):**
    *   Как пользователь, я хочу видеть список доступных мне групп контактов, чтобы выбрать получателей рассылки.
    *   Как пользователь, я хочу видеть количество контактов в выбранной группе, чтобы понимать охват.
    *   Как пользователь, я хочу вводить текст сообщения с счетчиком символов (ограничение SMS — 70/160 знаков), чтобы контролировать стоимость.
    *   Как пользователь, я хочу отправлять сообщение через свою SIM-карту, чтобы не платить за сторонние сервисы.
    *   Как пользователь, я хочу видеть статус отправки ("Отправлено", "Ошибка"), чтобы убедиться в успешной доставке.
*   **1.3. Функциональные требования:**
    *   Авторизация пользователя по логину/паролю.
    *   Получение списка групп контактов с сервера.
    *   Отображение списка групп с возможностью множественного выбора.
    *   Поле для ввода текста сообщения.
    *   Кнопка "Отправить".
    *   Экран статуса отправки.
*   **1.4. Нефункциональные требования:**
    *   Простой и интуитивно понятный интерфейс.
    *   Работа на Android и iOS (кросс-платформенная разработка выглядит предпочтительной).
    *   Безопасность передачи данных между приложением и сервером (HTTPS).
*   **1.5. Архитектура системы:**
    *   Мобильное приложение (клиент).
    *   Backend-сервер (API) для управления группами пользователей и контактами.
    *   База данных (например, PostgreSQL) на сервере.

## 2. Проектирование UI/UX
**Цель:** Создать простой и удобный интерфейс без лишних элементов.

*   **2.1. Карта экранов (Screen Flow):**
    1.  `Экран авторизации` -> 2. `Экран списка групп` -> 3. `Экран создания рассылки` -> 4. `Экран статуса`.
*   **2.2. Прототипирование (Wireframing):**
    *   **Экран списка групп:** Список чекбоксов с названием группы и количеством контактов (например, `[ ] Клиенты (- 150)`). Вверху поле поиска. Внизу кнопка "Далее".
    *   **Экран создания рассылки:** На верхней части экрана отображаются выбранные группы (можно нажать крестик, чтобы удалить). Основное пространство занимает многострочное поле для ввода текста. Под ним — счетчик символов (например, "Символов: 45 / 1 часть"). В самом низу — большая кнопка "ОТПРАВИТЬ ВСЕМ".
    *   **Экран статуса:** Список из имен контактов (или номеров) со статусом напротив каждого ("✅ Отправлено", "❌ Ошибка").
*   **2.3. Дизайн-концепция (Mockups):** Разработка визуального стиля в минималистичном ключе. Основной акцент на читаемость и удобство нажатия на кнопки.

## 3. Разработка Backend (Серверная часть)
**Цель:** Обеспечить работу API для мобильного приложения и интерфейса администратора.

*   **3.1. Технологический стек:** Node.js + Express / Python + Django / Go. База данных — PostgreSQL.
*   **3.2. Разработка API-эндпоинтов:**
    *   `POST /api/login`: Аутентификация пользователя.
    *   `GET /api/groups`: Возвращает JSON-список групп, доступных пользователю.
        ```json
        [
          { "id": 1, "name": "VIP-Клиенты", "contact_count": 25 },
          { "id": 2, "name": "Рассылка_октябрь", "contact_count": 150 }
        ]
        ```
*   **3.3. Административная панель (Web-интерфейс):**
    *   Создание/удаление пользователей приложения.
    *   Создание/редактирование/удаление групп контактов.
    *   Массовая загрузка контактов в группу (через CSV-файл).
*   **3.4. Модель базы данных:** Таблицы `Users`, `Groups`, `Contacts`, `User_Groups` (связь многие-ко-многим).

## 4. Разработка Frontend (Мобильное приложение)
**Цель:** Реализовать клиентскую часть согласно дизайну.

*   **4.1. Выбор технологии:**
    *   **Кросс-платформенная (*рекомендуется*):** Flutter или React Native. Позволит быстрее выпустить приложение под обе платформы с единым кодом.
    *   **Нативная:** Swift (для iOS) и Kotlin (для Android). Потребует больше ресурсов.
*   **4.2. Ключевые модули для разработки:**
    *   **Модуль авторизации:** Форма входа, сохранение токена сессии.
    *   **Модуль работы с сетью:** Сервисы для выполнения запросов к API (`login()`, `fetchGroups()`).
    *   **Экран "Группы":** Отображение списка, логика множественного выбора, запрос к API при открытии экрана.
    *   **Экран "Рассылка":**
        *   Приём ID выбранных групп с предыдущего экрана.
        *   Отображение названий выбранных групп.
        *   Поле ввода `TextField` с обработчиком изменений для счетчика символов.
        *   Логика сборки финального текста.
    *   **Интеграция с телефонией:** Самый ответственный модуль. Использование нативных возможностей ОС для отправки SMS:
        *   **Android:** Интент `ACTION_SENDTO` с URI `smsto:`. Это откроет стандартное приложение для СМС с уже заполненными получателями и текстом. Пользователь нажмет кнопку "Отправить" сам. Это самый безопасный и соответствующий правилам Google Play метод.
        *   **iOS:** Apple не предоставляет публичного API для прямой программной отправки SMS. Единственный легальный способ — использовать фреймворк `MessageUI` и контроллер `MFMessageComposeViewController`. Он также открывает системный интерфейс сообщений с предзаполненными данными.
*   **4.3. Модуль "Статус":** Так как отправка идет через системное приложение, точное получение статуса доставки затруднено. Можно реализовать ручной ввод результатов или оставить этот экран как подтверждение того, что данные были переданы в системное приложение для отправки.

## 5. Тестирование (QA)
**Цель:** Гарантировать стабильность и корректность работы приложения.

*   **5.1. Модульное тестирование:** Проверка отдельных функций (например, правильно ли работает счетчик символов).
*   **5.2. Интеграционное тестирование:** Проверка взаимодействия между модулями (приложение <-> API).
*   **5.3. Тестирование UI/UX:** Проверка удобства использования на разных экранах и размерах устройств.
*   **5.4. Тестирование на реальных устройствах:** Обязательная проверка функции отправки SMS на нескольких физических телефонах с Android и iOS.
*   **5.5. Нагрузочное тестирование API:** Симуляция одновременной работы нескольких десятков пользователей.

## 6. Релиз и публикация
**Цель:** Опубликовать приложение в сторах.

*   **6.1. Подготовка маркетинговых материалов:** Скриншоты, иконка, описание.
*   **6.2. Публикация в App Store и Google Play:** Прохождение ревью. Особое внимание нужно уделить описанию функции отправки SMS, чтобы модераторы поняли, что приложение не отправляет сообщения скрыто, а использует стандартный интерфейс телефона.

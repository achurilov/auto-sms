# План разработки мобильного приложения для автоматизированной рассылки СМС

## 1. Анализ требований и планирование

### 1.1. Функциональные требования
- Авторизация пользователей в приложении
- Просмотр списка доступных групп контактов (загружаются с сервера)
- Выбор одной или нескольких групп для рассылки
- Ввод текста сообщения
- Отправка СМС всем контактам выбранных групп через SIM-карту устройства
- Просмотр истории рассылок и статусов доставки
- Административная панель (веб) для создания и управления группами контактов

### 1.2. Технологический стек

**Мобильное приложение:**
- Android: Kotlin (нативная разработка рекомендуется из-за прямого доступа к SmsManager API)
- Альтернатива: React Native / Flutter с нативными модулями для отправки СМС
- *Важно:* iOS не позволяет программно отправлять СМС через код — только Android поддерживает эту функцию

**Backend:**
- Node.js / Python (Django, FastAPI) / Java (Spring Boot)
- База данных: PostgreSQL или MySQL
- REST API или GraphQL

**Административная панель:**
- Веб-приложение (React/Vue.js) для управления группами и контактами

## 2. Проектирование архитектуры

### 2.1. Серверная часть (Backend)

**Сущности БД:**
```
Users (пользователи мобильного приложения)
- id, login, password_hash, role, created_at

Groups (группы контактов)
- id, name, description, created_by, created_at

Contacts (контакты)
- id, name, phone_number, created_at

GroupContacts (связь групп и контактов, many-to-many)
- group_id, contact_id

SmsHistory (история отправленных сообщений)
- id, user_id, group_ids, message_text, sent_at, status
```

**API эндпоинты:**
```
POST   /api/auth/login              - авторизация
GET    /api/groups                  - получить список групп
GET    /api/groups/{id}/contacts    - получить контакты группы
POST   /api/sms/history             - сохранить историю отправки
GET    /api/sms/history             - получить историю рассылок

# Административные (только для admin role)
POST   /api/admin/groups            - создать группу
PUT    /api/admin/groups/{id}       - редактировать группу
DELETE /api/admin/groups/{id}       - удалить группу
POST   /api/admin/contacts          - добавить контакт
POST   /api/admin/groups/{id}/contacts - добавить контакт в группу
```

### 2.2. Мобильное приложение — архитектура

**Паттерн:** MVVM (Model-View-ViewModel)

**Слои:**
- **UI Layer** — Activity/Fragment/Compose экраны
- **ViewModel Layer** — бизнес-логика, состояние экранов
- **Repository Layer** — работа с API и локальным кэшем
- **Data Layer** — Retrofit для сети, Room для локального кэша

**Пример кода отправки СМС (Kotlin):**
```kotlin
fun sendSmsToContacts(contacts: List<Contact>, message: String) {
    val smsManager = SmsManager.getDefault()
    contacts.forEach { contact ->
        try {
            val parts = smsManager.divideMessage(message)
            smsManager.sendMultipartTextMessage(
                contact.phoneNumber,
                null,
                parts,
                null,
                null
            )
            // Задержка между отправками для избежания спам-фильтров
            Thread.sleep(200)
        } catch (e: Exception) {
            // Логирование ошибки для данного контакта
        }
    }
}
```

## 5. Обработка edge-кейсов и ограничений

- **Разрешения Android:** запрос runtime-разрешений SEND_SMS (Android 6.0+)
- **Ограничения оператора:** лимиты на количество СМС в сутки (некоторые операторы блокируют >30-100 СМС/сутки с одной SIM)
- **Двойная SIM-карта:** дать пользователю выбор, через какую SIM отправлять
- **Оффлайн-режим:** кэширование групп контактов локально (Room), чтобы приложение работало без интернета для отправки (только загрузка групп требует сети)
- **Дублирование номеров:** если контакт входит в несколько выбранных групп — дедупликация перед отправкой
- **Длинные сообщения:** разбивка на несколько частей (multipart SMS)

## 6. Тестирование

### 6.1. Виды тестирования
- **Unit-тесты:** бизнес-логика ViewModel, Repository
- **Интеграционные тесты:** взаимодействие с API
- **UI-тесты:** Espresso для критичных сценариев (выбор групп, отправка)
- **Тестирование на реальных устройствах:** разные версии Android, разные SIM-операторы
- **Нагрузочное тестирование backend:** большое количество запросов на получение групп

### 6.2. Тестовые сценарии
- Отправка сообщения одной группе
- Отправка сообщения нескольким группам одновременно
- Отправка при отсутствии интернета (группы не загружены)
- Отправка при отсутствии разрешения SEND_SMS
- Отправка большого количества СМС (проверка на блокировку оператором)
- Отправка длинного сообщения (multipart)

## ⚠️ Важные ограничения, которые стоит учесть заранее

1. **iOS не поддерживается** для программной отправки СМС — только Android
2. **Google Play Policy** ограничивает использование SEND_SMS permission — нужно либо стать SMS-по-умолчанию приложением, либо распространять вне Play Store
3. **Ограничения операторов** на количество СМС в сутки с одной SIM-карты
4. **Стоимость СМС** ложится на баланс SIM-карты пользователя (не через SMS-шлюз/агрегатор)

Если планируются большие объемы рассылки, стоит рассмотреть альтернативу — интеграцию с SMS-шлюзом (SMS-агрегатором) вместо отправки через SIM-карту телефона.
